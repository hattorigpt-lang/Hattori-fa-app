# FIRE & 資産運用 ライフイベントシミュレーター

資産推移・FIRE達成年齢・老後の取り崩し可能額を、ライフイベントとNISA・売却時課税まで織り込んで試算するブラウザアプリケーションです。

---

## 起動方法

ES Modules を使用しているため、`file://` での直接オープンでは CORS により動作しません。ローカルサーバー経由で開いてください。

```bash
# いずれかの方法で起動
python3 -m http.server 8000
npx http-server -p 8000
```

ブラウザで <http://localhost:8000/> を開きます。

### 設計方針

| 方針 | 内容 |
|---|---|
| 計算とDOMの分離 | `simulator.js` は DOM に一切依存せず、入力オブジェクトから結果オブジェクトを返す純粋関数のみで構成。Node からそのまま検証できます。 |
| 単一状態ストア | 状態の書き換えは `state.js` の `patch()` / `replace()` 経由のみ。グローバル変数への直接代入を排除しています。 |
| 宣言的なバインディング | HTML 側の `data-field="キー名"` が唯一の接点。要素IDを個別にキャッシュする必要がありません。 |
| 差分レンダリング | ライフイベント表は行を再利用し、グラフは `destroy()` せず `update('none')` で差分更新します。 |
| 定義の一元化 | 入力の許容範囲・FIRE目標タイプ・シナリオ定義は `config.js` に集約し、HTML と JS の二重管理を避けています。 |

## 検証

```bash
# 計算エンジンの回帰検証（20項目）
node tools/verify.mjs

# 静的解析
npx eslint js tools
```

`tools/verify.mjs` は、売却時課税モデルの手計算突合、シナリオ間の単調性、資産枯渇の検出、住宅ローンの償却計算、極端な入力での堅牢性など **29項目** を検査します。

計算エンジンが DOM に依存しないため、ブラウザを起動せずに数値の妥当性を確認できます。

## 計算モデルの前提

### 資産バケット

| バケット | 利回り | 課税 |
|---|---|---|
| 現金・預貯金 | 0%（固定） | なし |
| NISA口座 | 株式と同率 | 非課税（生涯枠1,800万・年間枠360万） |
| 株式・投信（課税口座） | 入力値 | 売却時に含み益へ 20.315% |
| その他運用資産 | 入力値 | 売却時に含み益へ 20.315% |

### 主要ルール（資産運用）

- **課税は売却時のみ。** 運用中は非課税で複利が働き、取り崩した金額のうち含み益に相当する部分にのみ課税します。取得原価は売却比率で按分して減額します。
- **積立順序** は NISA枠 →（枠を使い切ったら）課税口座。
- **取り崩し順序** は 現金 → 課税口座 → その他 → NISA。非課税の複利を最後まで温存する順序です。
- **FIRE達成判定** は、含み益への将来の税負担を差し引いた「税引後の実質資産」で行います。
- **シナリオ比較** は市況全体の想定として、リスク資産の利回りを一律に ±2 ポイントシフトさせます（標準＝入力値）。
- **「リタイア後に使える月額」** は、年金・インフレ・ライフイベント・売却時課税をすべて織り込んだうえで、想定寿命の時点で資産がちょうど尽きる水準を二分探索で逆算した値です。今日の物価に換算して表示します。

### 住居費・住宅ローン

住居費は「月間固定費」とは独立した支出ストリームとして扱います。利用者には固定費から家賃を除いてもらうことで二重計上を防ぎます（該当しそうな場合はUIが警告し、ワンクリックで差し引けます）。

- 購入までは家賃、購入後は「ローン返済＋維持費」を計上します。購入しない設定なら家賃が生涯続きます。
- 物件価格・頭金・諸費用は購入年までインフレで上昇します。一方、**ローン返済額は契約時に固定される名目額**のため以後は上昇しません（インフレ下で実質負担が軽くなる効果を再現）。
- 返済は元利均等。月次で償却スケジュールを計算し、住宅ローン控除の算定に用います。
- **住宅ローン控除**は年末残高（借入限度額3,000万円まで）× 0.7% を13年間、収入として加算します。所得税額を上限とする制度上の制約は考慮していません。
- **購入した住宅は金融資産に含めません。** 売却して生活費に充てられる資産ではなく、含めるとFIRE達成を過大評価するためです。
- FIRE目標額の基準となる生活費には、住居費の**経常分**（家賃 or ローン返済＋維持費）を含めます。頭金などの一時費用は含めません。

### モンテカルロ・シミュレーション

決定論モデル（毎年きっちり x% で運用）では、平均リターンが同じでも暴落がリタイア前後に来ると資産寿命が大きく縮む「シーケンス・オブ・リターン・リスク」を表現できません。

- 年次リターンを**対数正規分布**から抽選します。正規分布では -100% を下回るリターンが発生しうるためです。
- 算術平均とボラティリティから対数正規のパラメータを導出し、期待リターンが入力値と一致するよう補正しています。
- 乱数は**シード固定**です。入力を変えていないのに結果が揺れると比較できなくなるため、再現性を優先しています。
- FIRE目標額の算定には**期待利回り**を使い続けます（目標が乱数で揺れないようにするため）。
- 出力: FIRE達成率、資産枯渇率、達成年齢の10/50/90パーセンタイル、終端資産の分位、年次資産の10〜90%レンジ。

### 感度分析

各変数を単独で動かしたときの FIRE 達成年の変化を、影響の大きい順に並べます。金額系は ±10%、率系は ±1 パーセントポイントで変動させます。

資産曲線と目標額曲線の交点を**線形補間して小数年**で評価しています。年単位の丸めでは「現在の総資産 ±10%」のような小さなレバーの効果が 0年 に潰れて比較できなくなるためです。

## データの取り扱い

入力内容はブラウザの `localStorage` にのみ保存され、外部へ送信されません。「条件を共有」で生成されるURLは、状態を base64url へエンコードしてハッシュ部（`#`以降）に格納するため、サーバーへは送信されません。
